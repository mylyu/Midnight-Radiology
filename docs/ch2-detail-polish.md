## 实现与维护位置

### 数值与防误触

`app/src/game/interaction-transactions.ts` 将两章普通选择和普通翻页、第一章翻书/购买/维护变成可独立验证的纯事务。选择从当前节点重新核对条件，风险只用本次传入的随机值；选择效果、风险结果与目标游标写入同一状态。目标节点自身效果仍由进入节点时处理，不能提前标成已完成。

根 App 使用同步 `liveState` 读取最后提交状态，先计算一次、再整份保存和渲染；不再将带保存/随机副作用的操作放在 React 可重放的函数式 setter 内。第一章 NightScreen 保持同一夜组件，不再被每步 `resumeKey` 重挂载打断选项缓冲。

- 第一章全文显示后选项等待 900ms；普通翻页 300ms；两章商店及第一章维护 500ms。
- 被拒绝的快速点击不后移截止时间。不增加“显示全文/继续”按钮，仍点原文字显示全文、点原选项回答。
- `readCh1Book` 每夜真实 +1，持久旗标去重；医术 20 会变 21，不会退回 5。
- 满耐久不收费。95→100 只提示实际 +5，仍是原价 50；有实际维护时保留原家业 +1。
- 第一章库存型物品已持有时禁购；即时商品、五档彩票赔率与每夜五张额度保留。第二章沿用其独立商品用途/限购函数，只增加同步手势门槛。

### 无声提示

`stat-feedback.ts` / `StatFeedback.tsx` / `.css` 比较实际提交前后值，不直接显示计划奖励数。覆盖金币、医术、人心、家业、行动力与第一章耐久；不同动作最多保留三条、两秒淡出、无声音、不接收点击。

同一章/班次/目标游标，100ms 内的“选择效果＋目标进入效果”仅合并显示层，不合并或延迟存档事务；不同节点或正常隔开的购买独立显示。加载、切章、重玩初始化清空提示，不对导入的旧总值冒泡。不会把尚未显示的剧情或诊断文字用作冒泡理由。

桌面在顶部紧凑显示变化和原因；390px 手机上隐藏原因，仅显示准确增减，给影像和选项留空间。维护理由仅用于真实付费保养，冷却/换管球不误标成保养。
