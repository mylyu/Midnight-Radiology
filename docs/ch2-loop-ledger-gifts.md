# 第二章经营账本与当面送礼

本轮在 `codex/ch2-loop-parity`，基点 `05889fa`。仅本地实现；未推送、未部署。第一章/DR/DSA购买计数、成绩和进度不迁移、不重置。

## 账本接口

- `beginCh2Shift(state, shiftId, { recovered })` 必须在本班第一个剧情效果之前执行。开始快照固定；班后购物继续计入刚结束的班次，点击下一班才新建起始快照。
- `recordCh2Change(before, after, eventId, label, kind)` 将属性/物品/卡片/勋章/大事记与旗标变化和原始更新一起返回。已存在的事件标识返回 `before`，不能再次发钱。嵌套交易（如剧情入口兑现咖啡）在外层流水中剔除，避免重复列账。
- `CH2_CASE_COMPLETIONS` 提供 12 个现有交接节点的人类可读名称。即使本步无属性变化，也记一次 `case` 流水，不在出图前暴露病例答案。
- `settleCh2` 只记录结算与原有队列勋章，不再次发放剧情内班末补贴。五个班次照常进入 `settle`，晨会尾声才 `done`。
- 商店、咖啡兑现、晨会奖励在原会话函数内自行记账；答题选择和奖励防重仍沿用已持久化题序。旧存档无账本时以恢复点为起始，明确显示此前明细未记录；已通关档不倒退。

可选数据位于 `dlc.ch2.loop`，版本 1，包含本轮标识、逐班开始/结算快照、流水、送礼对象记录。不改变第一章全局字段意义。

## 对话送礼接口

- `ch2GiftChoices(state, node)` 只在硬编码白名单中的开诊前闲聊、午饭或交接空当产生选项，使用已有 `Choice` 格式；没有库存或同一同事本班已经收过新礼物则隐藏。
- `giveCh2Gift(state, node, choice.next)` 再次核验物品和场景，再扣物品并记录。新增零食送出人心 +1；奶茶只保留购买时的人心 +2；不额外消耗行动力。
- `dlc.ch2.giftReply` 保存原节点与人物回应，保证礼物送出后刷新仍能看到回应；继续后清除此字段，返回原闲聊。回应没有 `effect`，刷新不能再次扣物品或加属性。
- 小唐、老周、小雷、老范、小何均有配置。小何仅在原第三夜关东煮对话 `c2n3_k2` 增加奶茶选项，不替换原关东煮行动力、消耗、奖励和勋章链。
- 原 `shareCh2Item` 接口保留为无副作用兼容函数；班后背包不再出现分享按钮，只解释物品用途和下一次使用时机。
- 最后一个送礼场景为第五夜开诊前茶水间。该场景完成或进入患者流程后，奶茶与零食停售，已有库存不删除。

## 经营界面

`Ch2Settlement` 是第二章独立组件；复用已有背景及Tailwind样式，不改变共享经营引擎或全局样式。两列数值卡保留圆点观感并显示精确数字；班次记录可查新卡片、徽章、证物、重要选择、病例与收支。晨会后仍可访问手册、勋章、书页、背包、历史记录。旧版停颁收藏继续保留，不混入当前可获得分母。

展开账本时，中间内容区域独立滚动，底部功能菜单始终在视口内。菜单是 flex 正常文档流的一部分，不以浮层盖住最后一行记录；390px 竖屏使用紧凑三列布局与至少44px触控高度。`tests/ch2-settlement-layout.mjs` 检查桌面/390px的折叠、展开、滚到底部和商店关闭，并输出隔离截图到仓库外 `../ch2-settlement-layout-review/`。
